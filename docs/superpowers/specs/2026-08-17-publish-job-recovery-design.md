# 发布任务崩溃与中断恢复设计

## 背景

生产环境在发布成功的终态事件后继续写入日志，SSE 响应已结束却再次写入，触发 `ERR_STREAM_WRITE_AFTER_END` 并使管理后台进程退出。进程重启后，内存队列丢失，而 SQLite 中活动任务仍保持 `queued` 等状态，形成永不恢复的僵尸任务。

## 设计

1. 发布协调器在发送 `succeeded` 终态前写入最终成功日志，确保终态是该任务最后一次事件。
2. SSE 路由在终态事件到达时先解除订阅，再结束响应；所有写入前检查响应是否已经结束或销毁。
3. 发布路由注册时，将数据库中 `queued`、`validating`、`building`、`switching` 的历史任务原子更新为 `failed`，写入服务重启中断说明和完成时间。
4. 不自动重跑旧任务，因为快照可能不完整、代码版本可能变化，自动恢复会产生不可预测的发布结果。

## 验收标准

- 成功发布的最后一条事件包含最终日志且状态为 `succeeded`，之后不再发出事件。
- SSE 客户端断开或终态结束后，后续通知不会写入已结束响应。
- 服务重新注册发布路由时，遗留活动任务显示为失败并保留原日志。
- 新发布任务仍按原顺序串行执行。
