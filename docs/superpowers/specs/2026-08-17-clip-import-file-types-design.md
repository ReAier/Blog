# 剪切板导入文件限制与语言识别设计

## 背景

后台剪切板列表页通过隐藏的文件输入打开系统文件选择器。该输入当前没有 `accept` 属性，因此可以选择任意文件；选中文件后，导入表单的语言始终初始化为 `text`，需要人工修改。

本次修复仅调整后台客户端的文件选择和表单初始化行为，不改变剪切内容的存储结构、导入弹窗字段或 `/api/clips/import` 服务端接口。

## 目标

- 系统文件选择器仅展示后台编辑器支持的源码和纯文本文件。
- 代码层面对选中文件进行二次扩展名校验，避免依赖浏览器的 `accept` 提示机制。
- 根据文件扩展名自动填写导入弹窗的语言。
- 保留语言下拉框，允许用户在确认导入前手动调整识别结果。
- 对不支持的文件给出明确提示，不打开导入弹窗。

## 支持范围

| 语言值 | 文件扩展名 |
| --- | --- |
| `text` | `.txt` |
| `typescript` | `.ts` |
| `javascript` | `.js`, `.mjs`, `.cjs` |
| `tsx` | `.tsx` |
| `jsx` | `.jsx` |
| `python` | `.py` |
| `cpp` | `.c`, `.h`, `.cc`, `.cpp`, `.cxx`, `.hpp`, `.hxx` |

扩展名匹配不区分大小写。没有扩展名、以点结尾或扩展名不在白名单内的文件均视为不支持。

## 方案

### 集中维护文件类型规则

在 `admin/client/src/lib/languages.ts` 中维护扩展名到语言值的唯一映射，并从该映射导出：

- 文件输入使用的 `accept` 字符串；
- 根据文件名识别语言的函数。

这样语言下拉选项、支持的文件范围和自动识别规则位于同一模块，避免页面组件重复维护配置。

### 文件选择流程

`ClipsPage.tsx` 的隐藏文件输入使用导出的 `accept` 值。文件被选中后：

1. 从文件名最后一个扩展名识别语言，匹配时统一转为小写。
2. 若无法识别：清除当前导入文件和表单状态、重置文件输入值，并显示“不支持该文件类型”的状态提示；不打开导入弹窗。
3. 若识别成功：以去除最后一个扩展名后的文件名作为标题，使用识别出的语言初始化表单，并打开现有导入弹窗。
4. 用户仍可通过现有语言下拉框修改语言后提交。

选择同一个无效文件后应仍可再次触发 `change`，因此拒绝文件时必须清空原生文件输入的值。

### 服务端边界

本次不修改 `/api/clips/import` 的 MIME 类型策略或增加扩展名白名单。原因是服务端接口可能存在页面之外的调用方；直接收紧会产生额外兼容性影响。前端限制用于修复当前后台文件选择体验，而服务端仍保留原有上传大小与 MIME 校验。

## 测试策略

### 语言工具测试

扩展 `tests/admin-client-languages.test.ts`，验证：

- 每组受支持扩展名映射到正确语言；
- 大写和混合大小写扩展名可识别；
- 多个点的文件名按最后一个扩展名识别；
- 无扩展名、尾随点和未知扩展名返回未识别；
- `accept` 覆盖全部且仅覆盖已确认扩展名。

### 页面交互测试

扩展 `tests/admin-client-clips.test.tsx`，验证：

- 导入文件输入包含正确的 `accept` 属性；
- 选择支持的文件后打开导入弹窗，并自动填入标题和语言；
- 用户可以继续手动更改语言；
- 选择不支持的文件时不打开弹窗，并显示错误提示。

## 非目标

- 不通过文件内容猜测语言。
- 不支持无扩展名源码文件。
- 不新增现有编辑器之外的语言。
- 不改变剪切内容导入 API、内容 schema 或服务端错误码。
