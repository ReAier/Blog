# 文章内卡片统一与剪切板页面设计

## 1. 设计目标

在不大幅改变现有视觉和内容结构的前提下，统一题目卡片、剪切板卡片、外部引用卡片与折叠卡片的边框反馈；删除文章卡片中的重复操作按钮；让剪切板成为独立的新标签页辅助阅读页面，并使其代码区域延续正文代码块的半透明模糊材质。

设计原则：

- 统一现有视觉语言，不重做卡片布局。
- 保留各类卡片的信息结构和识别特征。
- 文章中的链接型卡片只负责内容预览和跳转。
- 复制、下载等代码操作集中在剪切板详情页。
- 折叠卡片保持现有原生交互和结构。

## 2. 统一边框反馈

适用范围：

- `.problem-card`
- `.clip-card`
- `.reference-card`
- `.callout-card`

统一状态：

1. 默认状态保留一层低对比度基础边框，确保无 hover 的触屏设备和弱背景区域仍能识别卡片边界。
2. 鼠标悬停时，外边框切换为与当前主题色一致的半透明边框。
3. `focus-within` 时使用比 hover 更明显的主题色边框，并保留统一的 focus ring。
4. 暗色模式沿用相同逻辑，仅调整阴影和透明度，避免边框过亮。
5. `prefers-reduced-motion: reduce` 下取消卡片位移，但保留边框颜色变化。

交互差异：

- 题目、剪切板和引用卡片可以保留轻微上移反馈。
- 折叠卡片不做整体上移，只增强边框或背景。
- 题目难度色继续用于左侧细线、光晕和题号水印；外边框统一使用网站主题色。

## 3. 题目卡片

题目卡片不改变现有信息结构：

- 平台链接。
- 题目标题链接。
- 分类标签。
- 难度色左侧细线、光晕与题号水印。

本次仅统一默认、hover 和 focus 的外边框行为，不增加或删除按钮，不改变 Markdown 字段格式。

## 4. 剪切板卡片

### 4.1 删除重复操作

从文章中的剪切板卡片删除：

- “查看完整代码”链接按钮。
- “复制代码”按钮。
- 整个 `.clip-card__actions` 操作区。
- 卡片内复制所需的数据属性和状态播报节点。

剪切板卡片保留：

- `</>` 类型标识。
- 语言、行数和文件大小。
- 标题。
- 可选描述。

### 4.2 链接行为

剪切板标题是唯一详情入口，并使用：

- `target="_blank"`
- `rel="noopener noreferrer"`

标题增加小型外开提示 `↗`，使新标签页行为可预期。卡片整体不包装为链接，描述文字仍可正常选择。

### 4.3 页面脚本

文章卡片不再执行复制操作。如果 `clip-copy` 脚本同时负责剪切板详情页的“复制全部”，则脚本继续保留并仅服务详情页；不得因为删除文章卡片按钮而破坏详情页复制功能。

## 5. 外部引用卡片

删除：

- “访问原文”按钮。
- `.reference-card__action` 操作区域及对应样式。

保留：

- 来源域名。
- 标题外链。
- 可选描述。
- 现有外链视觉标识。

标题继续在新标签页打开，作为唯一访问入口。卡片整体不包装为链接。

## 6. 折叠卡片

折叠卡片保持现有结构与交互：

- 继续使用原生 `details` 和 `summary`。
- 整个 summary 行负责展开和收起。
- 保留左侧图标与右侧箭头。
- 保留展开后的 Markdown 内容布局。

本次只统一外边框的默认、hover 和 focus 反馈，不改变内部间距、图标、箭头、开合逻辑或内容结构。

## 7. 剪切板详情页

### 7.1 新标签页工作流

文章中的剪切板标题在新标签页打开详情页。用户在详情页完成复制或下载后，可关闭标签页回到原文章，不需要页面内返回按钮。

### 7.2 操作区

保留：

- “复制全部”。
- “下载源码”。
- 复制状态的无障碍播报。

删除：

- “返回上一页”。
- `data-clip-back`。
- `clip-back` 脚本导入。
- 若该脚本未被其他页面使用，删除对应脚本文件及专属测试。

### 7.3 代码区域材质

剪切板详情页代码区域复用正文 `.prose pre` 的视觉材质：

- 使用 `var(--code-surface)`，不再固定为不透明 `#24292e`。
- 使用与正文一致的半透明背景逻辑。
- 使用 `backdrop-filter: blur(12px) saturate(120%)` 及对应的 WebKit 前缀。
- 使用相同的内高光和基础边框语言。
- 内部 `pre` 背景设为透明，确保外层模糊材质可见。
- 保留 Shiki 生成的 token 颜色，不覆盖语法高亮前景色。

剪切板详情页仍保留自身差异：

- 更大的代码内边距。
- 更高的最小高度。
- header 与代码区域上下连体的圆角结构。
- 详情页现有的元数据布局。

明暗主题都必须验证代码文字与背景的对比度。

## 8. 测试与验证

至少覆盖：

- 剪切板卡片不再输出卡片操作区和复制按钮。
- 剪切板标题包含新标签页属性和安全的 `rel` 属性。
- 引用卡片不再输出“访问原文”操作链接。
- 四类卡片都具备统一的 hover/focus 边框规则。
- 折叠卡片的原有结构、键盘交互和开合状态不变。
- 剪切板详情页仍包含复制与下载操作，但不包含返回入口。
- `clip-back` 脚本不再被加载。
- 剪切板代码区域使用半透明代码表面和 backdrop blur。
- reduced-motion 下不产生卡片位移。

验证命令：

```powershell
npm test -- --run
npm run check
npm run build
```

可见 UI 改动还需要在桌面端和窄屏下检查浅色、暗色主题。

## 9. 不在范围内

- 不重新设计四类卡片的内容布局。
- 不把题目、剪切板或引用卡片整体改为可点击链接。
- 不改变题目卡片的难度色系统。
- 不改变折叠卡片的结构与展开逻辑。
- 不删除剪切板详情页的复制和下载功能。
- 不修改剪切板 Markdown 定义格式、URL 路由或纯文本下载接口。
