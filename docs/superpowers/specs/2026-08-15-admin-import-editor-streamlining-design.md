# 后台内容导入与编辑器紧凑化设计

日期：2026-08-15

## 目标

修复文章 Markdown 导入对 frontmatter 过度严格的问题，并简化文章、剪切板及工作台界面，使独立资源的管理方式与当前内容模型一致。

## 范围

### 文章 Markdown 导入

文章导入同时支持以下格式：

1. 标准 frontmatter Markdown：沿用现有严格字段校验。
2. 文件开头存在 UTF-8 BOM 或空白行的 frontmatter Markdown：清理前导 BOM/空白后再解析。
3. 不含 frontmatter 的普通 Markdown：自动生成可编辑的默认文章信息。

普通 Markdown 的默认值：

- `title`：优先取正文中第一个 ATX 一级标题（`# 标题`）；没有一级标题时使用文件名。
- `slug`：由文件名去除扩展名后规范化为小写 kebab-case；无法生成有效 slug 时拒绝导入并给出明确错误。
- `description`：取正文第一个非标题、非代码块的普通段落并截断到 180 字；没有可用段落时使用标题，确保生成内容满足现有非空摘要约束。
- `publishedAt`：按 Asia/Shanghai 时区取导入当天日期。
- `tags`：空数组。
- `draft`：`true`。
- `featured`：`false`。
- `cover`、`updatedAt`：未设置。
- `body`：保留原始正文；用于标题推断的一级标题不从正文删除。

导入成功后文章列表刷新，并自动进入新导入文章的编辑页，方便补充摘要等必填信息。若目标 slug 已存在，沿用现有重复内容错误，不覆盖已有文件。

文章列表页的上传控件改为隐藏文件输入和紧凑的“导入”按钮，不显示“导入 .md”。

### 文章信息编辑器

- 删除 Slug 下方的迁移提示。
- 删除“草稿”和“首页精选”开关下方的解释文字。
- 缩小面板标题、字段间距、输入框高度和摘要高度；保持桌面端易扫读及移动端单列布局。
- 标签字段改为“管理标签”按钮：
  - 按钮旁显示当前已选标签块。
  - 点击打开弹窗。
  - 弹窗汇总所有现有文章使用过的标签，支持多选。
  - 提供新标签输入与添加操作。
  - 标签去重、去除首尾空白，空标签不保存。
- 封面字段改为“选择封面”按钮：
  - 复用图片库 API 获取已上传图片。
  - 弹窗显示缩略图、文件名及当前选择状态。
  - 选择后写入图片的 Markdown 路径。
  - 已选封面在字段内显示缩略图，并提供“更换”和“清除”。
- 正文工具栏现有“图片素材”选择功能保持不变；封面选择使用同一图片数据源，但不向正文插入 Markdown。

### 剪切板界面

- 所有面向用户的 `Clips`/`Clip` 导航和标题文案统一改为“剪切板”或“剪切内容”；内部路由、API、类型名和 Markdown 语法保持不变，避免无关迁移。
- 列表页移除长条 `<details>` 导入表单。
- 列表页顶部改为隐藏文件输入和紧凑“导入”按钮。
- 选择源码文件后打开小型导入弹窗，在弹窗中填写必要元数据并确认导入，不在页面中常驻长表单。
- 剪切内容编辑页压缩信息面板的空白和字段间距。
- 语言字段由自由文本输入改为下拉选择。初始选项包含：纯文本、TypeScript、JavaScript、TSX、JSX、Astro、HTML、CSS、JSON、YAML、Markdown、Bash、PowerShell、Python、C、C++、C#、Java、Go、Rust、SQL。
- 为兼容已有数据，下拉框额外显示当前未知语言值；保存时不擅自改写旧值。
- 删除“引用契约”提示框。

### 工作台

- 删除“待整理资源 / Content hygiene”整块内容。
- 删除底部 Editor's Note 提示。
- 统计卡片仍保留文章、剪切板、图片和发布状态数据。

## 组件与数据流

- 在文章解析模块增加“导入解析”入口；现有 `parsePostMarkdown` 继续作为严格存储格式解析器，避免降低仓库内容校验强度。
- `/api/posts/import` 调用导入解析入口，并传入文件名和上海时区当天日期。
- 文章编辑器加载文章列表和图片列表作为标签、封面选择器的数据源。选择器使用现有 dialog 样式和键盘关闭行为。
- 剪切板导入弹窗复用现有导入状态及 API，仅改变呈现方式。

## 错误处理

- 无法从文件名生成合法 slug：显示中文可操作错误。
- frontmatter 存在但格式错误：继续显示具体 frontmatter 校验错误，不静默退化为普通 Markdown。
- 普通 Markdown 缺少标题：使用文件名，不阻止导入。
- 标签与图片列表加载失败：编辑器主体仍可使用，选择器显示错误并允许重试。
- 导入、保存和资源加载继续使用现有状态提示区域。

## 可访问性

- 所有弹窗使用 `role="dialog"`、`aria-modal="true"` 和可关联标题。
- 打开弹窗后聚焦首个交互控件；Escape 关闭；关闭后焦点返回触发按钮。
- 标签和封面选择状态使用原生按钮及 `aria-pressed`/可读文本表达，不只依赖颜色。
- 隐藏文件输入仍由可聚焦按钮触发。

## 测试与验收

- 单元测试覆盖：BOM、前导空行、标准 frontmatter、无 frontmatter、一级标题推断、文件名标题回退、slug 规范化及格式错误 frontmatter。
- API 测试覆盖普通 Markdown 文件导入和重复 slug。
- 客户端契约测试覆盖两个“导入”按钮、不再出现“导入 .md”及长条导入表单。
- 编辑器测试覆盖标签弹窗、封面选择、语言下拉和已知/未知语言兼容。
- 视觉契约测试覆盖已删除提示与工作台区块、紧凑布局类名。
- 完成后运行：`npm test -- --run`、`npm run admin:check`、`npm run admin:build`、`npm run build`。

## 非目标

- 不迁移 `/clips` 路由或后端 API 命名。
- 不改变博客公开页面的剪切板 URL。
- 不自动上传新的封面图片；封面只能从图片库已有资源中选择。
- 不改变仓库最终保存的文章必须带合法 frontmatter 的规则。
