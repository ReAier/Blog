# 后台设置菜单设计

**日期：** 2026-08-17

## 目标

将单用户博客后台右上角的账户展示简化为单一“设置”入口，并把低频管理功能从主导航收纳到设置菜单中。

## 界面结构

- 删除右上角的用户名、“责任编辑”、圆形首字母头像和独立“退出”按钮。
- 在相同位置放置带齿轮图标的“设置”按钮。
- 从顶部主导航移除“备份”和“API 与安全”。
- 设置菜单按以下顺序展示：
  1. 备份
  2. API 与安全
  3. 分隔线
  4. 退出登录

## 交互

- 点击设置按钮切换菜单开关状态。
- 点击“备份”或“API 与安全”后进入现有页面并关闭菜单。
- 点击“退出登录”继续使用现有退出流程，成功后跳转登录页。
- 路由变化、点击菜单外部或按下 Escape 时关闭菜单。
- 设置按钮通过 `aria-expanded` 和 `aria-controls` 暴露展开状态；菜单使用合适的导航和可访问名称。
- 当前位于备份或 API 页面时，对应菜单项显示激活状态。

## 响应式与视觉

- 菜单锚定在设置按钮右下方，沿用后台现有面板、边框、圆角、阴影和主题变量。
- 桌面端和移动端使用同一设置入口；不会把备份/API 重新放入移动端主导航。
- 在窄屏下菜单保持在视口内，按钮维持可触控尺寸。

## 测试范围

- 验证主导航不再包含备份和 API 入口。
- 验证账户姓名、角色、头像和独立退出按钮不再渲染。
- 验证设置按钮能打开/关闭菜单。
- 验证备份与 API 菜单链接及当前页激活状态。
- 验证 Escape、点击外部、路由变化会关闭菜单。
- 验证菜单中的退出登录调用现有退出逻辑并跳转登录页。
