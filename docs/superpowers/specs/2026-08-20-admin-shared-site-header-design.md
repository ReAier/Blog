# 后台复用博客顶栏设计

## 背景

博客前台顶栏由 `src/components/SiteHeader.astro` 和 `src/styles/global.css` 实现；后台顶栏由 `admin/client/src/components/AppShell.tsx` 和 `admin/client/src/styles.css` 实现。两者已经共享 `src/styles/glass-material.css` 的玻璃材质变量，但顶栏布局、尺寸、导航激活态、按钮和响应式规则仍分别维护，导致后台视觉与博客前台不一致。

## 目标

让后台顶栏与博客前台使用同一套视觉样式，同时保留后台的导航目标、权限过滤、移动菜单、外观设置和设置菜单行为。

## 非目标

- 不把 Astro 组件直接移植到 React。
- 不改变后台路由、权限或登出逻辑。
- 不重做后台页面主体或其他卡片样式。
- 不让后台导入完整的前台全局样式，避免产生样式污染。

## 方案

### 共享样式边界

从前台 `global.css` 中抽出只属于顶栏的视觉契约，形成独立共享样式文件。该文件负责：

- 顶栏固定定位、页面边距和最大宽度；
- 顶栏玻璃表面、边框、圆角、阴影和模糊；
- 品牌标记的字体、颜色及强调点；
- 桌面导航的排列、文本、悬停和激活指示线；
- 右侧图标按钮的尺寸、边框、圆角和交互状态；
- 紧凑状态、移动断点和减少动画偏好。

前台 `global.css` 和后台 `styles.css` 都导入该文件。共享文件只使用明确的顶栏类名，不包含文章、卡片或页面主体规则。

### 结构契约

前台与后台保持各自框架组件，但对齐共享类名：

- 顶层：`site-header`
- 玻璃容器：`nav-shell glass`
- 品牌：`site-mark`
- 主导航：`site-nav`
- 右侧操作区：`header-actions`
- 通用方形按钮：`icon-button`

后台可保留 `admin-header`、`admin-nav` 等兼容类名，用于后台专属行为和现有测试，但视觉由共享类名承担。后台导航链接继续使用 React Router 的 `NavLink`，通过 `aria-current="page"` 或共享激活类驱动与前台相同的底部强调线。

### 后台专属扩展

后台继续保留：

- “工作台 / 文章 / 剪切板 / 图片库 / 发布与日志”导航；
- 权限过滤；
- 当前位置辅助文本；
- 外观设置按钮及面板；
- 设置按钮、设置菜单和登出入口；
- 移动端菜单展开、路由切换关闭及 Escape 关闭行为。

“当前位置”文本继续供辅助技术使用，但桌面视觉中不占据额外空间。设置按钮采用共享图标按钮材质，并允许在足够宽的桌面尺寸显示“设置”文字；窄屏只显示图标。

## 视觉行为

- 桌面端尺寸、圆角、间距与前台顶栏一致。
- 后台激活导航由当前块状填充改为前台式底部强调线。
- 悬停状态保持克制，不新增独立后台色块。
- 主题按钮与设置按钮使用同一种外框、背景和悬停反馈。
- 移动端保持可操作性，导航展开层级不得遮挡设置面板或编辑器关键操作。
- 支持 `prefers-reduced-motion`，导航指示和按钮过渡可被禁用。

## 测试策略

先添加失败测试，再修改实现：

1. 验证前台和后台样式入口都导入同一个共享顶栏样式文件。
2. 验证后台 `AppShell` 应用了共享结构类名，同时保留后台导航、设置和权限逻辑。
3. 验证共享样式包含顶栏容器、导航激活指示、图标按钮和响应式契约。
4. 运行相关 Vitest 测试、`npm run admin:check`、`npm run admin:build` 和完整 `npm run build`。

## 风险与控制

- **全局类名冲突**：共享文件仅包含顶栏命名空间和明确的子选择器。
- **现有后台规则覆盖共享规则**：删除或收敛重复的后台顶栏视觉声明，仅保留行为和后台专属扩展。
- **响应式回归**：保留移动菜单逻辑，并通过契约测试覆盖关键断点规则。
- **工作区已有修改**：只改动顶栏相关文件和新增测试，不回退或重写现有未提交修改。

## 完成标准

- 后台顶栏在桌面端视觉与博客前台一致。
- 两端实际引用同一份顶栏样式，而非复制代码。
- 后台导航、权限、外观设置、设置菜单和移动菜单功能保持不变。
- 相关测试、类型检查及生产构建通过。
