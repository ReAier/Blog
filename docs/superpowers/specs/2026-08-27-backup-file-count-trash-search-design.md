# 备份文件数与回收站搜索设计

## 目标

修复管理后台备份列表中历史 ZIP 的文件数全部显示为 0 的问题，并为回收站增加与文章列表一致材质的搜索框。

## 范围

### 备份文件数

- `GET /api/backups` 在列出历史 ZIP 时读取 ZIP 内的 `manifest.json`。
- 返回 `manifest.files.length` 作为 `fileCount`，与创建备份接口保持一致。
- `manifest.json` 不计入文件数。
- 单个历史备份清单损坏、缺失或格式不兼容时，列表接口仍然返回该备份记录，并使用安全的回退值，不阻塞其他备份显示。
- 新创建备份的现有 `result.fileCount` 行为保持不变。

### 回收站搜索

- 在回收站的类型筛选工具条中加入搜索框。
- 复用文章搜索使用的 `search-field post-title-search` 类名和视觉材质。
- 搜索范围为项目标题和详情文本，采用去除首尾空格后的不区分大小写模糊匹配。
- 搜索与类型筛选叠加。
- 类型计数继续基于全部回收站项目，不随搜索词变化。
- 没有匹配项时显示专门的空状态提示。

## 方案

备份数量属于服务端 ZIP 内容事实，因此在备份路由层读取并解析归档清单；回收站数据量通常有限，搜索只在已加载的回收站数组上完成，不新增 API 参数或服务端搜索逻辑。这样可以最小化接口变更，并直接复用已有文章搜索的无刷新交互与样式。

## 失败处理

- 读取历史 ZIP 清单失败时记录安全回退的 `fileCount`，不让一个异常归档导致整个列表请求失败。
- 搜索为空或只有空白字符时显示当前类型筛选下的全部项目。
- 搜索后无结果时显示“没有匹配的回收站内容”类提示，并保留类型筛选和搜索框。

## 验收标准

1. 已存在的正常备份在列表中显示 `manifest.files.length`，不再固定为 0。
2. 新创建备份的文件数仍与清单文件数一致。
3. 回收站可按标题或详情模糊搜索，且可与类型筛选同时使用。
4. 搜索框外观与文章列表搜索框一致，并具备可访问的标签。
5. 备份清单异常不会让历史备份列表接口整体失败。
6. 相关 Vitest、`npm run check` 和生产构建通过。
