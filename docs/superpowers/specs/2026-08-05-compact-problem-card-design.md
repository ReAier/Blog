# 紧凑题目卡片设计

## 1. 设计目标

将文章中的算法题卡片设计为紧凑、易扫读的 Online Judge 条目。卡片应延续博客现有的暗色玻璃、衬线标题和主题色体系，但不能表现为高大的横幅或复杂的操作面板。

核心目标：

- 降低卡片高度与无效留白。
- 清晰区分平台、题名和分类标签。
- 利用右侧题号水印平衡横向空间。
- 不展示冗余的难度文字或大按钮。
- 保持键盘访问、移动端适配和减弱动画支持。

## 2. 最终信息结构

卡片从上到下排列：

1. 题目平台链接，例如 `LUOGU ↗`。
2. 题目名称，例如 `A+B Problem`。
3. 题目分类标签，例如 `# 模拟`。
4. 右侧大号半透明题号水印，例如 `P1001`。

示意：

```text
LUOGU ↗

A+B Problem
# 模拟

                                  P1001
```

题号水印不参与文档语义，对屏幕阅读器使用 `aria-hidden="true"`。

## 3. 内容解析规则

Markdown 题目卡片继续使用现有字段：

```problem
title: P1001 A+B Problem
url: https://www.luogu.com.cn/problem/P1001
difficulty: red
categories: 模拟
```

渲染器从 `title` 开头识别题号：

- `P1001 A+B Problem` 拆分为题号 `P1001` 和题名 `A+B Problem`。
- 题号仅用于右侧装饰水印，不在左侧重复显示。
- 无法识别题号时，完整标题作为题名显示，并且不生成水印。
- 分类字段支持英文逗号和中文逗号，重复分类自动去重。

平台名称根据 URL 主机名推导：

- `luogu.com.cn` → `LUOGU`
- `codeforces.com` → `CODEFORCES`
- `atcoder.jp` → `ATCODER`
- `leetcode.com` / `leetcode.cn` → `LEETCODE`
- 其他网站显示去除 `www.` 后的主机名。

## 4. 视觉规范

### 4.1 卡片容器

- 使用现有玻璃表面和背景模糊效果。
- 外边框使用当前站点主题色，而不是题目难度色。
- 默认边框透明度约为 50%，hover 和 focus 时增强。
- 圆角保持与其他文章内嵌卡片一致。
- 桌面端内边距控制在约 `18–22px`，避免形成 Banner 感。

### 4.2 难度表达

不显示“红色难度”等文字，也不显示难度圆点。

难度仅通过以下装饰表达：

- 左侧 3px 渐变细线。
- 右上角低透明度光晕。
- 右侧题号水印颜色。

难度颜色不得覆盖主题色边框。

### 4.3 平台链接

- 放置于题名上方。
- 使用小号等宽字体和较宽字距。
- 默认使用弱化文字颜色。
- hover 时切换为主题色，箭头轻微向右上移动。
- 不额外显示“查看题目”按钮。

### 4.4 题目名称

- 使用博客现有衬线字体。
- 与平台链接保持紧凑间距。
- 字号使用约 `1.3–1.65rem` 的响应式范围。
- 题名本身作为题目链接，在新标签页打开。

### 4.5 分类标签

- 放置在题目名称下方，而不是题号旁边。
- 使用小号等宽字体。
- 使用主题色低透明度边框和背景。
- 多个标签允许自动换行。
- 必须显式覆盖 `.prose ul` 的默认上下外边距，避免卡片异常增高。

### 4.6 题号水印

- 位于卡片右侧中部。
- 使用等宽粗体。
- 字号约为 `4–7rem` 的响应式范围。
- 使用对应题目难度颜色。
- 默认透明度约为 7.5%，移动端降低到约 5.5%。
- 不可点击、不可选择、不阻挡鼠标事件。
- 允许接近右侧边缘，但必须被卡片圆角和 `overflow: hidden` 裁切。

## 5. 响应式规则

在窄屏设备上：

- 卡片内边距缩小至约 `17–18px`。
- 题名与平台间距进一步收紧。
- 水印字号缩小，并降低透明度。
- 标签保持在题名下方并自动换行。
- 不引入独立右栏，避免压缩题名可用宽度。

## 6. 交互与无障碍

- 平台和题名链接均使用 `target="_blank"` 与 `rel="noopener noreferrer"`。
- 所有链接保留可见的键盘焦点状态。
- 水印使用 `aria-hidden="true"`，避免重复朗读题号。
- `prefers-reduced-motion: reduce` 下取消卡片位移与箭头动画。
- 难度不能只通过文字之外的交互状态表达；其装饰性颜色不承担操作含义。

## 7. 开发与缓存约束

题目卡片由 remark 插件生成 HTML。修改 `src/lib/remark-problem-card.ts` 后，Astro 已缓存的内容可能仍包含旧结构。

开发命令应使用：

```powershell
npm run dev
```

项目的 `dev` 脚本配置为 `astro dev --force`，启动时清理内容层缓存。不要同时启动多个 Astro 开发服务器。

生产验证使用：

```powershell
npm test -- --run
npm run check
npx astro build --force
```

## 8. 不在范围内

- 不修改 Markdown `problem` 代码块字段格式。
- 不增加通过率、提交数、来源图标等新数据字段。
- 不增加 JavaScript 交互或第三方依赖。
- 不把整个卡片包装为嵌套链接。
- 不恢复右侧大按钮、难度文字或难度圆点。
